SendMessage выполняется синхронно: отправитель ожидает обработки сообщения потоком приёмника. Пока отправитель заблокирован, планировщик сохраняет контекст его потока — значения регистров, указатель стека и положение выполнения, необходимые для продолжения работы. Процессор может выполнять другие потоки. После завершения ожидания контекст восстанавливается, и отправитель продолжает работу после вызова SendMessage.

PostMessage помещает сообщение в очередь и возвращает управление без ожидания его обработки. В нашем примере обработчик быстро завершает процесс приёмника через os._exit(0), поэтому по внешнему поведению двух запусков разница почти незаметна.
